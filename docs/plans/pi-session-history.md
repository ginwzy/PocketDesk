# Pi 会话回退与分支切换：完整实施计划

状态：功能代码已实现，服务端、Flutter 自动验证与桌面浏览器联调已完成；安卓真机安装联调待设备验证。

## 1. 交付目标

在同一个 PocketDesk Pi 会话内，手机和电脑均可回到历史对话位置、修改消息重新发送、查看和切换历史分支。原历史保留，切换结果跨端同步，断线或重启后恢复正确的当前分支。

一次完整交付上述能力，不以“仅创建独立分叉会话”替代原会话内导航。内部按依赖顺序实施，各阶段完成不等于最终交付。

会话回退只改变 Pi 的对话上下文。文件内容、执行过的命令和外部操作不随之撤销。文件恢复不属于本次功能，界面必须明确说明。

## 2. 已核实的基础与限制

- 手机：Flutter，聊天页面 `app/lib/ui/pages/chat_page.dart`，消息归并 `app/lib/data/chat.dart`，同步 `app/lib/core/sessions_store.dart`。
- 电脑：`server/internal/httpapi/web/admin/app.js`，已有消息右键菜单和按事件序号加载历史的流程。
- 公共后端：Go `server/internal/session`、`server/internal/store`、`server/internal/httpapi`。
- Pi：`server/internal/agent/pi.go` 使用常驻 RPC 进程；`pi_effort.go` 已实现带请求编号的 RPC 请求与响应关联。复用时将其中专用的思考强度错误描述移到操作层，避免导航失败显示成强度设置错误。
- PocketDesk 事件 `seq` 是递增同步游标；Pi 会话树用稳定的 `entryId`、`parentId`、`leafId`。两者含义不同，不能相互替代。
- 现有手机删除消息是本地隐藏，不影响 Pi 上下文，不能用来实现回退。
- 本机安装的 Pi 提供 `get_tree`、`get_entries`，可以取得历史树和当前叶节点。
- 本机 Pi RPC 没有直接提供 `navigate_tree` 命令，但 RPC 模式的扩展命令上下文提供 `navigateTree`，可以通过 PocketDesk 内置扩展桥接。
- 已查阅的 Pi 实现中，导航到用户消息会把当前叶节点移到其父节点，文本用于编辑；导航到非用户节点会把该节点作为当前叶节点。扩展命令上下文只返回取消状态，不能假设直接取得底层 `editorText`。
- Pi `navigateTree` 可选择生成分支摘要。严格回退默认不生成摘要，以免旧分支内容再次进入上下文。
- 本机版本的能力不代表所有用户版本都支持。正式实现必须握手检测，不能仅按版本字符串推断。

## 3. 用户交互与语义

### 3.1 消息操作

| 目标 | 操作名 | 行为 |
| --- | --- | --- |
| 用户消息 | 修改并重试 | 回到该消息之前；原始输入恢复为草稿；由用户主动发送 |
| 完整助手回复 | 从这里继续 | 保留到该回复对应的有效对话边界，允许输入新的消息 |
| 历史分支 | 切换到此分支 | 恢复该分支的实际保存位置，展示其历史 |

默认不提供在工具调用中间导航的按钮。高级历史详情可以展示底层节点，但服务端只接受已验证能构成有效上下文的可导航位置，避免不成对的工具调用/结果。

“修改并重试”与“恢复分支”必须是不同语义：若分支末尾恰为用户消息，恢复分支必须恢复到该用户消息之后，不能错误复用“导航用户消息会回到父节点”的规则。桥接验证阶段必须解决精确恢复叶节点问题；必要时提供单独的扩展操作，并验证 Pi 的公开接口，不直接篡改 JSONL。

### 3.2 入口

- 手机：消息长按菜单；会话更多菜单中的“历史分支”；分支切换后顶部显示当前分支入口。
- 电脑：消息右键菜单；会话顶部“历史分支”入口；宽屏侧栏、窄屏弹层。
- 两端 `/tree` 打开同一个历史分支选择器，由客户端或服务端控制路径处理，不能将它当普通提示词发送给模型。
- 分支列表展示消息摘要、时间、当前标记和分叉位置，默认折叠思考与工具细节；不强制手机显示复杂树图。
- 选择节点先预览，再执行；浏览历史不改变 Pi 当前上下文。
- 原分支保留可回访位置。一次切换尚未产生新消息时，也不能让原位置从列表中丢失。

### 3.3 文案

修改用户消息的确认说明：

> 回到这条消息之前，并将原消息放回输入框。原来的后续对话会保留在历史分支中。已修改的文件和已执行的命令不会撤销。

按钮：“取消”“回到这里”。成功提示：“已回到所选位置，可以修改后发送”。

切换其他分支时显示“切换到此分支”；失败和被扩展取消时明确反馈，不能展示成功提示或丢失当前草稿。

### 3.4 草稿与原始输入

- 仅发起操作的客户端接收并应用编辑草稿；另一端同步分支状态，但不覆盖其正在输入的内容。
- 若发起端已有草稿，保留原草稿并显式让用户选择替换或取消，不能静默覆盖。
- PocketDesk 发送前会组合附件、skills 和预设指令。恢复编辑使用 PocketDesk 保存的原始用户输入，不能把组合后的 Pi prompt 当原文再次发送。
- 恢复可用附件引用与 skills；缺失附件显示明确提示，不自动丢弃。无法还原原始结构的旧会话提供明确降级说明。
- 新消息发送携带预期的当前分支版本。其他端刚切换分支时，拒绝过期发送，保留草稿并提示刷新。

## 4. Pi 桥接与能力验证

新增内置扩展（建议 `server/internal/agent/pi_history.ts`），按现有 embed 和缓存写入方式加载。

先用临时 Pi 会话完成不调用付费模型的最小实测：

1. RPC 模式加载扩展，握手报告树查询、导航、精确恢复位置的能力。
2. 通过扩展命令调用 `ctx.navigateTree`，验证普通导航和被扩展取消。
3. 验证消息完成后、返回首条用户消息之前、根为空、分支叶为用户消息时的行为。
4. 确定请求与完成响应的桥接通道。必须有独立请求 ID、完成/取消/失败结果；不能把普通 `prompt` 的接收应答误当导航完成。
5. 控制请求不得进入模型对话或触发生成；响应不得混入普通聊天气泡。若利用扩展 UI 通知承载结果，需要先于现有 `piUIRequest` 的忽略逻辑分流，并只识别约定的桥接消息。
6. 完成后回读 Pi 的 `leafId`、会话文件和所需配置，验证实际位置；扩展可修改导航行为，不能只凭请求目标计算最终状态。
7. 验证保存后关闭并重启 Pi，当前分支能够准确恢复。失败时补齐持久化恢复路径后再进入 UI 实施。

能力不支持时提供明确升级提示，隐藏或禁用对应按钮。不得退化成仅隐藏气泡、截断文件或把控制命令交给模型执行。

## 5. 数据与同步设计

### 5.1 三类状态分开维护

- 传输事件：继续保持 PocketDesk `seq` 单调递增，保留审计与增量同步语义，不删除或倒退事件游标。
- Pi 历史树：原生节点 ID、父节点、消息类型、内容及当前 `leafId`，作为模型会话历史的权威来源。
- 当前视图：从当前叶节点沿父链生成聊天投影；切换时重建当前分支展示，不能把所有时间顺序事件继续拼在一条对话里。

维护 `historyRevision`，在影响当前分支视图或有效导航目标的变化发生时推进。读接口返回版本，写接口校验预期版本。具体存储结构按现有迁移机制实现，不改变其他 Agent 的历史行为。

### 5.2 关联和归并

- 为 Pi 用户消息、助手消息、工具调用和轮次建立原生节点与 PocketDesk 事件关联。
- 不依赖文本相等、数组下标或当前 `pi-N` 临时消息编号定位节点；相同文本重复发送必须可区分。
- 原始用户输入、附件、skills、clientId、审批及改动卡片保留为 PocketDesk 元数据，绑定到正确节点或轮次。
- Pi 历史压缩、摘要、自定义消息和模型/强度节点需正确归并；展示完整历史与实际模型上下文不必相同，不能假装压缩前原文全部仍在上下文中。
- 失败、取消和未提交到 Pi 的用户消息单独标识，不提供无效回退入口。
- 流式增量只作用于所属分支/轮次。导航前清空或隔离残余流式状态，迟到事件不能污染新分支。

### 5.3 旧数据与大历史

- 既有 Pi 会话首次使用历史功能时，从 Pi 获取树并建立关联；没有可靠关联的旧气泡不按文本猜测，可从原生历史选择器选择明确节点。
- 当前分支历史和分支列表支持分批加载。Pi 若只能返回完整树，服务端缓存并索引；客户端不必一次接收所有工具输出。
- 覆盖本地隐藏消息、搜索、复制、全选、工具详情、审批和改动卡片在分支切换后的归属。
- 不可访问的 Pi 文件或损坏的父链提供可诊断错误或只读展示，不能清空已有 PocketDesk 历史。

### 5.4 断线恢复

建议发布带版本、当前叶节点和操作 ID 的 `session.history.changed` 事件，提示客户端重新获取权威快照。

快照包含同步水位 `lastSeq`。订阅与快照读取按水位衔接，避免快照期间的新消息丢失或重复；过期版本的事件不得覆盖新投影。手机离线缓存保存所属版本，重连时发现分支变化则刷新投影。

## 6. 后端操作与接口

在 Agent 适配层增加可选 HistoryController 能力，由 Pi 实现，不强迫其他 Agent 提供空实现。

建议统一接口（最终名称可按现有路由习惯调整）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/sessions/{id}/history` | 能力、当前位置、版本与分支摘要 |
| `GET /api/sessions/{id}/history/entries` | 当前或指定分支的历史预览、分页 |
| `POST /api/sessions/{id}/history/navigate` | 修改用户消息、从回复继续或恢复分支 |
| `GET /api/sessions/{id}/history/operations/{operationId}` | 断线或超时后查询确定结果 |

写请求包含 `operationId`、`expectedRevision`、目标节点及明确操作类型；返回权威的新版本、实际叶节点、取消状态和发起端可用的草稿信息。

- 手机与 admin 路由复用相同 Manager 实现和鉴权边界。
- 校验节点属于当前 Pi 会话，不接受客户端传入任意会话文件路径。
- 会话级串行化发送、导航、模型设置与生命周期操作；使用明确状态避免死锁。导航期间不持有会阻塞 Pi 事件消费的锁。
- 正在生成、压缩、自动重试、执行命令、等待审批、处理中断或有待发队列时禁止切换；返回可解释的 busy 状态。用户可通过已有停止流程结束工作后重试。
- 相同 operationId 重复提交返回原结果；版本冲突返回冲突错误，不静默覆盖另一端选择。
- 导航后回读 Pi 实际模型、思考强度等受导航影响的设置，协调 PocketDesk 会话显式覆盖值，确保界面与下一次发送配置一致。

### 6.1 跨 Pi 与数据库的一致性

Pi 文件修改与 PocketDesk 数据库不能共享事务，采用可恢复操作记录：

1. 持久化 pending 操作、旧位置、目标与预期版本。
2. 执行 Pi 导航并回读实际状态。
3. 事务更新当前位置、版本、历史关联与操作结果。
4. 提交后广播两端刷新事件。

超时不等于未执行。遇到响应丢失、进程退出或数据库写入失败，将会话标为待协调；禁止继续发送，回读 Pi 或重启恢复后完成协调，再返回确定结果。服务重启扫描 pending 操作。不能仅重试导航或只把界面切回旧位置。

## 10. 实现与验证记录

实现采用以下具体协议，不改变本计划的同会话导航目标：

- Pi 内置 `pi_history.ts` 扩展桥接 `navigateTree`；导航前后追加不进入模型上下文的保存位置，支持恢复末尾为用户消息的分支和空根，不创建新的 Pi 会话文件。
- `leafId` 校验选点快照，`branchId` 校验发送所属分支。普通回复推进叶节点不改变分支版本，避免正常续聊被误判为跨分支发送。
- `history.reset` 提供当前路径的权威投影，`history.bind` 关联流式气泡与原生节点。完整投影不在每轮重复写入，原生绑定与原始输入同时保存在 Pi 自定义记录中。
- SQLite 的 `history_operations` 保存幂等操作与待协调结果，`history_state` 独立保存当前分支身份，避免事件归档清理掉并发保护。
- 四个历史 HTTP 接口已接入手机及 admin 共用路由；预览接口支持按固定目标路径分页。桌面历史列表分批渲染，手机采用惰性列表。
- 原始草稿、附件、skills、所属分支和未确认操作在客户端持久化。其他端切换不会覆盖当前输入；历史附件失效时保留引用并提示重新附加。
- 扩展取消不报告成功；正在执行、审批或中断中拒绝导航。没有导航能力的 Pi 不会退化为隐藏气泡或截断会话文件。

## 11. 历史树交互改进

将倒序消息列表替换为按用户请求分组的真实分支树，统一由服务端沿 Pi 父链整理轮次，跳过工具和内部保存位置。树上保留原生导航目标，根节点可表示首条消息之前，末尾用户消息的恢复能力保持不变。

- 当前路线默认展开，其他路线折叠；唯一的当前位置标记、连续父级连线和分叉横线避免把兄弟路线误读为先后消息。
- 折叠路线显示末条请求与最后更新时间；搜索保留祖先结构，并可定位当前节点。
- 电脑左右分栏，手机独立预览页。预览展示所选位置的实际对话路径，较长路径先加载末尾并可继续加载更早内容；工具与思考默认折叠。
- 明确选择“修改并重试”“从这里继续”或“切换到此分支”之后才进入最终确认，重复选择当前上下文不会发起导航。
- 验证：真实 Pi 分叉浏览器联调、双客户端同步与草稿保留、响应丢失恢复、390px 窄屏，以及 Flutter 的折叠、搜索、预览只读与当前位置操作测试。

本轮最终验证：Go 全量测试与真实 Pi 集成通过，38 项 Flutter 测试通过；使用正式打包的 macOS 应用启动隔离服务完成浏览器联调，补验了迟到的预览响应不会覆盖新选择，以及取消确认后返回原预览。手机尚未进行真机安装交互验证。
