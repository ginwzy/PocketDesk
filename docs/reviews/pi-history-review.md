**Pi 历史功能 review 与优化记录**

范围：当前未提交的历史导航、分支树、预览、跨端同步和相关子进程改动。以下问题已经修复，修订保存在工作区。

1. **P1：满事件队列可能导致导航失败后的进程清理死锁。**

   `NavigateHistory` 持有会话锁关闭旧 Pi，并等待 `Done`，以避免旧进程延迟改变会话位置。如果标准输出读取线程阻塞在已满的事件队列上，而事件消费者正在等待会话锁，读取线程无法走到 `Wait`，`Done` 就不能关闭。

   在共享 `lineProc` 中新增独立的关闭通知，显式关闭时解除事件发送阻塞；进程真正退出后才发布 `Done`，保留原来的退出确认。真实子进程持续输出并填满队列、暂停事件消费的复现用例，从关闭超时变为正常完成。见 `server/internal/agent/proc.go`、`proc_test.go`。

2. **P1：手机长会话刷新可能永久停在较早的位置；并发补拉的 await 也可能提前返回。**

   `EventsBefore` 需要带上当前分支快照，但最多返回 5000 条事件。原来的 `_resync` 把这一页当作完整同步结果，没有继续补拉。实际复现：远端最新序号为 7000，刷新后停在 5099。

   现在刷新会继续追到已知远端游标；同一会话的并发 `catchUp` 调用共享一个 Future，调用方等待的是同步完成。首次加载复用 `_resync`，保持聊天投影对象不变，并统一处理迟到的 HTTP 响应，减少两套刷新规则的分歧。两个新增复现用例均先失败、修复后通过。见 `app/lib/core/sessions_store.dart`、`app/test/core/history_resync_test.dart`。

3. **P2：预览和导航校验耦合了整棵树的构建，分页规则重复分散在两个客户端。**

   原先预览调用完整 `historyView`，同时计算树和聊天事件；长历史还需先取第一页获知总数，再请求最后一页。手机和电脑分别维护偏移计算、重叠裁剪，以及额外请求。

   已将纯树结构计算 `historyOutline` 与单路径事件投影 `historyEvents` 分开。预览不再构建分支树，导航校验不再读取聊天投影，事件投影只解析当前路径的原始输入。新增服务端 `before` 游标，`-1` 表示末页，响应中的 `before` 用于请求更早一页；两个客户端直接使用返回的游标，不再计算偏移或裁剪重叠。手机最终确认复用已经加载的预览内容和提示。

   真实浏览器验证：长历史首次预览由 2 次请求降为 1 次；分三页取得 86 条消息，无重复或遗漏，Pi 当前位置保持不变。旧的 `offset/limit` 请求仍然可用。见 `server/internal/session/history_projection.go`、`history.go`、`app/lib/ui/pages/history_page.dart` 和桌面 `app.js`。

4. **P2：已知的业务拒绝被包装成笼统的 500，旧图片编辑失败后还会困在待恢复操作中。**

   会话文件丢失的实际 HTTP 响应原来是 `500 internal / 操作失败，请稍后重试`。现在返回 `409 history_file_unavailable` 及恢复原文件的提示。旧原生图片缺少附件路径时返回 `422 history_image_unavailable`；客户端清除这类确定未执行的请求，允许重新选择历史位置。

   浏览器实测了旧图片被拒绝后刷新历史、选择前一回复并成功导航。真正结果不确定的操作仍保留操作编号，继续通过幂等恢复处理；服务端同时记录等待恢复的具体原因。见 `server/internal/httpapi/common.go`、`server/internal/session/history.go` 及两端导航错误处理。

5. **简化重复状态和序列化。**

   删除只写不读的运行时 `historyLeaf` 字段。`history.reset` 直接构造需要的叶节点、分支身份和聊天事件，不再把包含整棵树的响应序列化、反序列化，再删除字段。
